OpenAI 在 2026 年 11 月 4 日推出 Images 2.6，距離 9 月 8 日的 Images 2.5 不到兩個月。ChatGPT 與 Codex 的所有訂閱方案同一天換上新版，API 則多了兩個新模型：GPT-Image-2.6 Flare 和 GPT-Image-2.6 Sunburst。

版本號只跳了 0.1，網路上的說法卻很多：有人說快了一半，有人說低畫質貴了四倍，也有人說審查變嚴了。這篇回到 OpenAI 自己公布的文件逐項讀：發表文、API 文件（模型頁、生圖指南、參數規格、更新紀錄與停用時程）、2.6 和 2.5 兩份系統卡，以及官方論壇的發表串。

> 文中把資訊分成三種：官方文件寫的、社群量到但官方沒證實的、編輯部自己的推論，每一處都會標明。OpenAI 沒有公布 2.6 的架構和畫質評測分數，文中不替它補。資料查詢日為 2026 年 11 月 28 日。

## 一、先講結論：快了、好控制了、多了兩種輸出

四份文件讀完，2.6 的改動可以收成三件事：

1. **更快**：官方說出圖快 50%，Flare 在低畫質下最快六秒一張。
2. **更好控制**：新增 `complexity` 參數，決定模型動筆前想多久；ChatGPT 裡的圈選標註編輯（markup）也開放給 API。
3. **多兩種輸出**：會動的 GIF，以及可以再編輯的向量圖 SVG。

沒變的也不少：每個 token 的單價一樣，兩個模型的分工（Flare 求快、Sunburst 求細）一樣。系統卡也說，安全機制沿用 2.5，只為 GIF 多加了一層。逐項對照如下：

| 項目 | 2.5（2026-09-08） | 2.6（2026-11-04） |
|---|---|---|
| 速度 | Flare 延遲比 gpt-image-2 少一半 | 「比以前快 50%」 |
| Flare 定位 | 多數應用的預設選擇 | 快速迭代，版面改善 |
| Sunburst 定位 | 更精準，出圖較慢 | 細節多的作品 |
| complexity | 無 | low／medium／high |
| GIF | 無 | 有（API 須申請預覽） |
| SVG | 無 | 有（僅限 API） |
| 圈選標註編輯 | ChatGPT 推出 | 開放給 API（2.5 也可） |
| token 單價 | 圖片輸出每百萬 30 美元 | 相同 |
| Batch 五折 | 支援 | 不支援 |
| 固定版本快照 | 有 | 無 |
| 尺寸上限 | 長邊 3840 像素 | 相同 |

## 二、快 50%：跟誰比、快在哪

發表文的原話是 Images 2.6「比以前快 50%」。這個「以前」沒有寫明是 2.5 的哪個模型、哪種畫質，也沒有附測試方法；論壇發表串同樣只寫「出圖快 50%」。把它讀成「比 2.5 快一半」很合理，但這不是官方給過的精確比較。

官方給的具體數字只有一個：**Flare 在 `quality`（畫質）設為 low 時，最快六秒出一張圖**。

兩個模型的分工也寫得更細：

- **Flare**：給快速迭代用。發表文另外提到，Flare 在海報、商品圖這類講究版面的專業視覺上有改善。
- **Sunburst**：給細節多的作品用。發表文說它畫質更高、跨輪編輯的一致性更好，但加了一個條件：**畫質設在 medium 或 high 時**。換句話說，用 low 畫質跑 Sunburst，未必拿得到它的優勢。

最直覺的分工因此是：Flare 跑草稿，Sunburst 出定稿。

## 三、complexity：畫之前想多久

2.6 最值得注意的新東西，是一個叫 `complexity`（複雜度）的參數。API 文件的說明是：它控制「圖像模型在渲染之前做多少規劃」。可選 low、medium、high 三級，**不設的話兩個模型都用 high**，調整它不另外收費。

它和原本的 `quality` 是兩回事：

- `quality` 管渲染：細節、清晰度、精細程度。
- `complexity` 管構思：場景裡要放多少東西、物件之間的關係怎麼安排。

官方的建議很具體：多數編輯工作用 **low**，速度快，再搭配你需要的畫質；元素多、限制多的場景，例如密集的文字、複雜的版面，才試 medium 或 high。文件同時提醒，complexity 開得高會變慢，**也可能帶來你沒要求的改動**。

API 文件附了一組範例：同一段紙雕風格的足球慶祝場景，用 Sunburst、medium 畫質，只換 complexity。照官方的圖說，low 是紅衣球員在前景高舉頂著皇冠的獎盃，「CHAMPIONS」橫幅橫過前景；medium 的獎盃換成月桂花環，球衣多了隊徽；到了 high，前景的球員換成藍色紙摺球衣，「CHAMPIONS」的牌子移到後方看台。同一段提示詞，模型想得越多，自己做的決定也越多。

系統卡對這個功能的說法是「可調整的推理強度」（configurable reasoning effort）：ChatGPT 使用者在模型選單裡調，API 開發者透過參數調。對照 API 文件，API 端指的應該就是 `complexity`。

**對創作者的意義**：預設值是 high。只想改招牌上的一個字、換個背景，卻沒有特別設定，模型就會用最高的規劃強度處理，可能順手動到你沒要求的地方。做小修改時，明確把 complexity 設成 low，比較符合官方的建議。

## 四、GIF：會動了，但不是影片

### 能做什麼

在 ChatGPT 裡，2.6 可以把一段提示詞或一張圖變成 GIF 動畫，還能調整速度、修改個別影格（官方論壇發表串）。API 端則是把輸出格式設成 `gif`，生圖和編輯兩個端點都能用；想用靜態參考圖帶動畫，就走編輯端點。

API 的主要參數：

| 參數 | 範圍 | 預設 |
|---|---|---|
| 影格數 `frame_count` | 2–16 格 | 9 格 |
| 每格時間 `frame_duration_ms` | 20–2000 毫秒 | 200 毫秒 |
| 每格尺寸 `size` | auto 或 16 的倍數 | auto |

API 參考文件裡有一句要注意：使用 GIF 輸出「需要取得該模型的 GIF 預覽權限」。也就是說，GIF 在 API 端目前還是要開通的預覽功能，不是每個帳號都能直接呼叫。它也不支援串流、局部預覽、遮罩（mask）和自訂壓縮。

### 16 格有多長

預設的 9 格、每格 200 毫秒，一輪是 1.8 秒，官方範例裡那隻提燈籠的猴子就是這個設定。上限是 16 格：

- 每格 100 毫秒（每秒 10 格），一輪 1.6 秒。
- 照電影的每秒 24 格算，16 格只有三分之二秒。
- 想拉長，只能把每格放慢，畫面就越來越像幻燈片。

所以 GIF 適合循環的小動作：眨眼、揮手、吉祥物打招呼、商品轉一圈。發表文列的用途也是這些：品牌吉祥物、社群用的反應圖和梗圖，還有一項影像創作者用得上的：**在正式做影片之前，用動態分鏡探索角色的動作**。拿它來試角色怎麼轉身、表情怎麼變，確定了再交給影片模型，是比較實際的用法。

### 推論：它可能是先畫一張分格圖

這一小節是編輯部的推論，官方沒有說明 GIF 是怎麼生成的。

線索有兩條。第一，發表文展示的 GIF 範例（由合作夥伴 OpenArt 製作）附了提示詞，兩段都寫成「製作一張用於無縫循環 GIF 的動畫 sprite sheet（分格圖）」：6 格排成 3 欄 2 列、每格同尺寸、固定機位、第六格要能接回第一格。第二，API 文件規定，影格數、每格尺寸和動畫數量都要塞進模型的尺寸限制與「單次請求的總像素預算」，超過就得減少格數或縮小每格。

兩條合起來看，2.6 的 GIF 很可能是在一張大圖裡把所有影格畫出來，再切開組成動畫。如果是這樣，可以預期兩件事：格數越多，每格的解析度越低；同一張圖裡畫出來的影格，角色和背景應該相當一致。這兩點都還需要實測確認。

### 審核比靜態圖嚴

系統卡為 GIF 專門寫了一節：動畫會帶來單張靜態圖看不出來的風險，例如帶性暗示的動作，或是要連著幾格看才看得出來的有害意涵。因此部分類別在 GIF 上擋得比靜態圖更廣，把「推想出來的動作」也算進去。做打鬥、受傷這類動作場面時，GIF 被拒的機會可能比同題材的靜態圖高。

## 五、SVG 與圈選編輯：設計稿用得上的兩個功能

### SVG：先畫圖，再請另一個模型寫成向量

把輸出格式設成 `svg`，2.6 就會交出向量圖，適合圖示、標誌、插畫這類之後還要調路徑、形狀、顏色的素材。做法 API 文件寫得很清楚：**先由圖像模型畫一張點陣的參考圖，再由另一個「撰寫模型」照著寫成 SVG**。`quality` 和 `complexity` 管的是那張參考圖；撰寫模型另有自己的推理設定，用量也分開回報。

限制不少：

- 只能在 API 的生圖端點用，發表文和系統卡都只說 API 支援。
- 一次只能出一張，不支援串流和局部預覽。
- 不能拿 SVG 去編輯，編輯端點也不收 SVG 當輸入。
- 交出來的是純靜態向量：不含程式碼、外部資源，也不嵌點陣圖。

費用是兩段相加：參考圖照圖像模型計價，寫 SVG 的 token 照撰寫模型計價。

### 圈選標註編輯：在圖上畫圈，告訴它改哪裡

2.5 推出時，ChatGPT 就能直接在圖上標註要改的地方；2.6 把這個功能開放給 API。做法是準備一張和原圖同尺寸的透明 PNG，在要改的地方畫上記號，跟原圖一起送進編輯端點，再用文字說明怎麼改。官方範例是在廚房照片的花瓶外畫一個紅圈，提示詞要求把圈裡的條紋花瓶改成純鈷藍色陶瓷、其他保持不變，成品裡也要拿掉紅圈。

API 的這個功能，2.5 的兩個模型也能用，不另外收費，但不能和傳統的遮罩同時使用。

## 六、帳單：單價沒變，每張不一定

### 官方：單價一樣

2.6 兩個模型的 token 單價和 2.5 完全相同：

- 圖片輸出：每百萬 token 30 美元
- 圖片輸入：每百萬 token 8 美元（快取 2 美元）
- 文字輸入：每百萬 token 5 美元（快取 1.25 美元）

不過 API 文件自己也提醒：單價相同，不代表每張圖價格相同，因為不同模型、不同畫質用掉的 token 數不一樣。官方建議看每次回應裡的 `usage` 欄位自己量。

### 社群：低畫質的 token 多了好幾倍

OpenAI 開發者論壇的一位資深使用者（不是 OpenAI 員工）在發表隔天貼出實測：同樣的畫質設定，2.6 的輸出 token 在 **low 是 2.5 的 4.2 倍、medium 是 3.3 倍**，high 以上則相同。他舉的例子是一張 medium 畫質的圖，2.5 用了 344 個輸出 token，2.6 用了 1,136 個。OpenAI 沒有回應，也沒有證實這組數字。

如果這組數字成立，2.6 的 low 和 medium 就不再是便宜的草稿選項：單價沒漲，每張卻貴了三到四倍。

### 沒有 Batch、沒有固定版本，文件也只寫 Image API

另外三個差異是從模型頁和生圖指南讀出來的：

- **不支援 Batch API**：2.5 可以走 Batch，價格打五折（圖片輸出每百萬 token 15 美元），2.6 目前不行。大量出圖、不急著拿結果的工作，2.5 反而便宜。
- **沒有帶日期的快照**：2.5 有 `gpt-image-2.5-sunburst-2026-09-08` 這種鎖定版本的名稱，2.6 目前只有 `gpt-image-2.6-sunburst` 一個別名，沒辦法鎖定版本。系列作品要長期維持一致風格的話，得留意這個名字背後的模型日後可能更新。
- **文件只寫 Image API**：2.5 的模型頁寫明可以當 Responses API 生圖工具的模型；2.6 的文件只說新功能透過 Image API 提供，生圖指南介紹 Responses API 時舉的也還是 2.5。要做多輪對話式編輯的開發者，先確認自己的帳號能不能用。

### 舊模型的停用時間

OpenAI 的停用時程表，把 2.6 列為下列舊模型的建議替代：

| 舊模型 | API 停用日 |
|---|---|
| gpt-image-1.5、gpt-image-1-mini | 2026-12-01 |
| chatgpt-image-latest | 2026-12-01 |
| gpt-image-2 | 2027-02-10 |

前三個是 6 月就宣布的，gpt-image-2 則是 11 月 10 日才宣布。2.5 目前不在停用時程表上。

## 七、系統卡讀什麼

### 系統卡是安全說明書，不是規格書

OpenAI 每推出一個重要模型，就會在「部署安全中心」發一份系統卡，內容是安全評估、防護措施和限制。它不寫架構，也不放畫質評測分數，想從系統卡讀出「2.6 畫得比較好」是讀不到的。

2.6 的系統卡只有九頁。開頭對能力的描述是：編輯一致性、細節保留，以及對草圖和圖上標註的理解都有改善；接著明說，安全機制建立在 2.5 的基礎上，再為 GIF 加上額外防護。

### 安全機制：兩道關卡

和 2.5 一樣分成上下游兩段：

- **上游**：請求送進生圖模型之前，先由大型語言模型檢查是否違反政策，違反的直接拒絕。
- **下游**：一個專門訓練來判斷意圖和內容政策的「安全推理模型」，檢查所有輸入的文字和圖片，也檢查最後產出的圖，任一關判定違規就擋下。

2.6 卡裡寫到的新措施是：ChatGPT 生圖時，在既有審核之外，**同步執行兒少性剝削內容（CSAM）的分類**。

### 評測數字：Sunburst 降、Flare 升，都不顯著

OpenAI 用同一套 3,077 條刻意設計來誘發違規圖的提示詞，讓 2.6 的兩個模型各自和 2.5 的同名模型比。最關鍵的指標是「產出違規圖，而且沒被審核擋下」的比例，越低越好：

| 模型 | 2.5 | 2.6 |
|---|---|---|
| Sunburst | 1.92% | 1.72% |
| Flare | 1.49% | 2.14% |

Sunburst 略降；Flare 從 46 張升到 66 張。系統卡說，兩者的差異在統計上都不顯著。

但另一個數字是顯著的：**在審核介入之前，Flare 畫出合規圖的比例從 78.36% 降到 75.04%**。多出來的違規圖主要落在兩類：「其他」（宗教人物、宗教諷刺、捏造或醜化真人的圖、越獄嘗試等）和性內容。多出來而且沒被擋下的 20 張裡，有 14 張屬於「其他」。

白話地說，2.6 的 Flare 比較「敢畫」，多畫出來的違規圖大部分被審核攔下，但沒攔住的也多了一點。對一般創作者可能的影響是：在真人、宗教這類邊緣題材上用 Flare，生成後才被擋的情況可能比較常見。這是編輯部依數字的推論；系統卡也強調，這些刁鑽提示詞不代表一般使用的情況。

### 「審查變嚴了」？擋下率不等於嚴格度

發表隔天，有使用者在官方論壇引用系統卡的數字抗議：性內容的限制從 75.13% 提高到 87.30%。這組數字是 Flare 在性內容類別「產出違規圖並被擋下」的比例。

同一列還有另一個數字：Flare 在這一類畫出合規圖的比例，從 24.34% 掉到 12.70%。也就是說，被擋下的比例變高，主要是因為模型更常畫出越線的圖，不是審核標準變嚴。對使用者來說，結果一樣是被擋；但要改善的是模型的畫法，不是放寬審核。OpenAI 客服的回覆也是：這不必然代表限制變多了。

### GIF 的偵測率：77.7%

GIF 防護用一組標為違規的刁鑽 GIF 來測，結果是偵測到的比例（召回率）：

| 類別 | 偵測率 |
|---|---|
| 整體 | 77.7% |
| 性內容 | 77.8% |
| 自我傷害 | 77.5% |
| 仇恨／辱罵 | 90.9% |
| 暴力／血腥 | 89.7% |
| 極端主義 | 92.9% |
| 暴力活動 | 96.6% |

系統卡自己承認：和動作有關的違規仍然難以偵測，防護不一定抓得到全部。

### 前沿風險：沒到高風險，仍照高風險管

OpenAI 的「整備框架」（Preparedness Framework）追蹤三類嚴重風險：生物與化學、資安、AI 自我改進。圖像模型的測法有點意思：讓模型生成一張圖，圖裡要寫出推理過程和最終答案，再只批改圖中的答案。結果兩個模型都沒有達到生物和資安的「高風險」門檻；但 OpenAI 沿用 2.0、2.5 的做法，仍以生物「高風險」等級的防護來管理。

### 浮水印：不是新的

系統卡寫 2.6 的圖會帶 C2PA 內容憑證，加上 Google DeepMind 的 SynthID 隱形浮水印，ChatGPT、Codex 和 API 都有。這兩項在 2.5 的系統卡就寫了，不是 2.6 新增的；2.6 卡只多了一句：讀者可以用 OpenAI 的公開驗證工具檢查檔案。

C2PA 是寫在檔案裡的中繼資料，重新存檔或轉檔就可能消失；SynthID 則嵌在像素裡。不管哪一種，作品要標示 AI 生成時，還是要照發布平台的規定另外標註。

### 2.5 卡有、2.6 卡拿掉的

- **「新的安全挑戰」一節**：2.5 卡寫明，寫實度提高後，政治、性或其他敏感的真人深偽影像可能更逼真。2.6 卡沒有這一節。
- **生物風險即時封鎖的準確率**：2.5 卡說它的召回率和精確度與文字模型的同類系統相當，2.6 卡沒有再寫。

拿掉不等於風險消失，只能說這份卡沒有再討論。

### 讀數字的陷阱：兩份系統卡不能直接比

這是讀系統卡最容易踩的坑。2.6 卡裡當對照組的「2.5」數字，和 2.5 卡自己公布的數字對不上：

| 2.5 模型的漏網率 | 2.5 卡自己寫 | 2.6 卡的對照組 |
|---|---|---|
| Sunburst | 1.09% | 1.92% |
| Flare | 1.41% | 1.49% |

原因是評測方法換了。2.5 卡拿 2.5 和 2.0 比，測的是「端到端的安全系統」，統計沒有做多重比較校正；2.6 卡改用固定的 3,077 條提示詞和共同的評分程序，測的是「部分正式上線的審核檢查」，也做了多重比較校正。所以只能看同一份系統卡內部的比較，不能把兩份卡的數字放在一起，說 2.6 比 2.5 安全或不安全多少。

## 八、官方沒說的

讀完這些文件，以下幾件事官方都沒有提：

- **架構和訓練方法**：兩份系統卡的訓練資料段落幾乎逐字相同，沒有任何架構描述。
- **畫質評測**：沒有分數、沒有排行榜數字，只有「畫質更高」「一致性更好」這類描述。
- **色彩雜訊有沒有修**：本站〈[GPT 生的圖為什麼看起來髒？](/post/gpt-image-color-noise/)〉整理過 GPT Image 2 與 2.5 的色雜訊和亮度斑駁。2.6 的發表文、系統卡和 API 文件都沒有提到這件事，編輯部也還沒有系統性地實測 2.6 的圖。
- **4K 算不算正式支援**：兩代的尺寸上限相同（長邊 3840 像素、總像素約 830 萬）。API 文件只把「2.5 超過 2560×1440」標成實驗性，沒有說 2.6 的情況。

## 九、給創作者的建議

1. **草稿用 Flare，定稿用 Sunburst 的 medium 以上**。官方說 Sunburst 的優勢要在 medium、high 畫質才顯現。
2. **小修改把 complexity 設成 low**。預設是 high，可能順手改到你沒要求的地方。
3. **把 GIF 當動態分鏡**。16 格的上限只夠做循環小動作，拿來測角色的轉身和表情，確定了再交給影片模型。
4. **大量出圖前自己量 token**。看回應裡的 `usage`；需要 Batch 五折的批次工作，目前只有 2.5 能走。
5. **還在用 gpt-image-1.5 的 API 程式，12 月 1 日前要換掉**。
6. **系列作品記下用的模型與日期**。2.6 目前沒有固定版本的快照。

## 常見問題

**ChatGPT 免費版能用 Images 2.6 嗎？**

**答**：發表文寫的是 2.6 已在 ChatGPT 與 Codex 的「所有訂閱方案」全球上線，涵蓋桌面、手機和網頁；各方案的用量額度，發表文沒有另外說明。

**complexity 和 quality 差在哪？**

**答**：quality 管渲染的細節和精細程度，complexity 管模型動筆前做多少規劃，也就是場景裡放多少東西、怎麼安排。兩者可以分開調。complexity 不另外收費，但開高會變慢，也可能改到你沒要求的地方。

**2.6 的 GIF 能拿來做影片嗎？**

**答**：不太適合。上限 16 格，以每秒 10 格算只有 1.6 秒，適合循環的小動作，或在做影片前先用動態分鏡測角色動作。API 端的 GIF 目前還是要申請的預覽功能。

**2.6 會比 2.5 貴嗎？**

**答**：每個 token 的單價一樣，但每張圖用掉的 token 數可能不同。論壇使用者實測 low、medium 畫質的輸出 token 是 2.5 的三到四倍，OpenAI 沒有證實；2.6 也不支援 Batch 的五折價。實際成本請用回應裡的 usage 自己量。

**系統卡說 2.6 比較不安全嗎？**

**答**：沒有這樣說。Sunburst「產出違規且沒被擋」的比例略降，Flare 略升，兩者在統計上都不顯著；顯著的是 Flare 在審核介入前畫出違規圖的比例變高。另外，2.6 卡和 2.5 卡的評測方法不同，兩份卡的數字不能直接比。

**2.5 還能用多久？**

**答**：截至 2026 年 11 月 28 日，OpenAI 的停用時程表沒有列出 2.5，API 的圈選標註編輯也同時支援 2.5。即將停用的是 gpt-image-1.5、gpt-image-1-mini、chatgpt-image-latest（2026 年 12 月 1 日）和 gpt-image-2（2027 年 2 月 10 日）。

**2.6 的圖還會有色彩雜訊嗎？**

**答**：官方文件沒有提到雜訊有沒有修，編輯部也還沒有系統性實測。遇到斑駁時，可以試試本站的〈[AI 圖片色雜訊診斷與降噪](/resource/ai-image-denoise/)〉工具。
